category: Added
- **Stride AdjustWeek prompt context builders** - New `internal/stride/adjust_prompt.go` assembles the prompt for adjusting one week of an existing 26-week macro block, alongside the instruction text that governs it: the standing half-marathon priority in one sentence, the adjustment rules (reduce when ACR is above 1.3, two or more key sessions were missed, an `overtraining`/`injury_risk`/`hr_too_high` flag appeared or a note reports illness; add at most 10% when the athlete was fully compliant and ACR is below 0.8; never change the week's phase; propose phase or goal changes with a reason instead of applying them), and the `{week, adjustment{deviates, summary, goal_update}}` output envelope. The athlete-facing sections — profile, treadmill calibration, race prediction, workout library, constraints, custom prompt, unconsumed weekly notes, the previous week's plan and the last 14 days of evaluations — are reused verbatim from the weekly generator, which now renders them through shared helpers so the two prompts cannot drift apart. Everything derived is summarised in Go to keep the prompt around 7-8k tokens: the macro block (current goal revision, the mesocycle rendered as "Build 2, week 2 of 4, focus ...", the target week's spec and the weeks either side of it), one progress row per elapsed block week (planned versus actual km, planned versus completed sessions, threshold minutes and flag count, with any column whose lookup failed rendered as `n/a` under an explicit "DATA UNAVAILABLE" note rather than as a zero the coach would read as missed training), fitness signals (ACR now plus a four-week trend, training status, half-marathon prediction and VO2max both now and at the block's start), and the previous four weeks' adjustment summaries so the coach does not oscillate. The library rule "suitable for the current training block" is now instantiated with the target week's actual block instead of staying abstract. Raw workouts and laps, the full 26-week history table, chat transcripts and the legacy `goal_race_*` preferences are deliberately excluded. The assembled weekly generation prompt is byte-identical to before, so plan generation is unchanged; nothing calls the new builders yet. (Hytte-ndzgk)
