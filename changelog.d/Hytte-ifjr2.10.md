category: Removed
- **Goal Race settings replaced by the Stride race calendar** - The Goal Race block in Settings → Training (race name, date, distance, target time) is gone, along with the `goal_race_name`, `goal_race_date`, `goal_race_distance` and `goal_race_target_time` preferences behind it. Stride's race calendar is the only place races are recorded now, and the macro plan's own goal is what training is aimed at, so the AI profile block, the workout-insights prompt and the race-prediction prompt no longer carry a second, contradicting goal race. Rows written for the removed keys before this change are deleted on startup — with the settings UI gone and the preferences allow-list dropping new writes, they would otherwise linger forever in the preferences API and the data export with no way to remove them. (Hytte-ifjr2.10)

category: Added
- **Stride switches in Settings** - Enable Stride, training days per week (1–7) and the weekly distance cap (1–500 km) are now editable under Settings → Training for users with the Stride feature. They previously had to be written into the database by hand, because the preferences API refused any key outside its allow-list. Out-of-range days or caps and a non-boolean enable value are rejected with a clear error rather than silently stored. The Stride custom prompt and treadmill calibration moved into the same block, so every Stride-only preference is now shown together. (Hytte-ifjr2.10)

category: Security
- **Stride preferences are feature-gated server-side** - `PUT /api/settings/preferences` now rejects every `stride_*` key with 403 for a user who lacks the Stride feature, instead of relying on the UI to hide the controls. `stride_enabled` is the one preference that recruits background work — the weekly Stride job picks athletes by that value alone — so a user without Stride could previously enrol themselves in it through the API. (Hytte-ifjr2.10)
